# 日切放行

> 遵守 `ops/底座生成前必读_效率与技术栈.md`。FastAPI + Vue 3 + SQLite，交付须 docker compose 一键起；库用 SQLite，不挂外置 Postgres。  
> **禁止同构换皮**：本仓主链路、表结构、接口与页面均独立，不得与其它仓共用同一套 `/api/items` 壳。

## 骨架一句话

业务日分区切片登记后裁决完整度，完整才放行下游；签收回执按策略簿定口径闭环，并与消费水位对账

## 签收回执闭环（口径定死，禁止混签）

签收策略簿 `ack_strategy` 为单行不可变记录（SQLite 触发器物理禁改禁删），首次落簿在甲/乙两路中二选一，改口一律 409 并写入偏差簿：

| 口径 | 甲方案（签收推水位） | 乙方案（放行即推水位） |
|------|--------------------|----------------------|
| 放行成功时 | 只改正式放行态，**不推水位** | 立即推水位 |
| 签收成功 | 这是甲口径水位的唯一推进点 | 只追加只读回执，不重复推水位 |
| 拒签 | 正式放行态回退「未放行」+ 记拒签，全链路无水位 | 不改正式放行态/水位，开回拨工单；工单待处理期间该消费方禁止再推水位 |
| 无签收 | 水位页不得出现该消费方已消费读数 | 水位存在但签收列表明确显示「待签收」 |

- 策略簿未锁定前，放行、签收、工单全部入账动作冻结（409 + 偏差留痕）
- 放行/签收/工单写库过同一把进程内互斥锁：两名值班同时提交，后到一方显式收到「签收争用」409，绝不静默成功
- 回执唯一约束（一个放行一条回执），只读不可改删
- `GET /api/reconciliation` 逐行对读放行详情、签收列表、水位页三处读数；不符即列出违规项
- 偏差簿 `ack_deviations`：策略未定先入账、策略改口、重复签收、签收争用、未完整放行、重复放行、回拨工单未闭环、拒签回退/回拨、口径越权，全部即拦即记
- 老库原地迁移：`releases`/`watermarks` 补列、历史流水补签收态；锁定策略时按所选方案做历史补录（甲补回执挂接旧水位，乙补缺的水位），本地文件库继续沿用

## 为何能出多题

迟到切片、重切、跨分区依赖、部分完整冻结、消费水位回拨

## 避开

别做成作业拓扑编排换皮；别做成纯水位大盘

## 互斥切口候选

- 迟到切片整批拒收 vs 进待补齐冻结区
- 重切失败整笔回滚 vs 保留已完整分区
- 放行与水位同步闸 vs 异步放行后纠偏

## 页面与接口

页面导航：签收策略 / 切片登记 / 完整度裁决 / 下游放行（放行详情）/ 签收回执（含回拨工单）/ 消费水位 / 对账对读；页头常驻策略旁注。

| 接口 | 说明 |
|------|------|
| `GET/POST /api/ack/strategy` | 读策略簿 / 首次定稿即锁，改口 409 |
| `POST /api/slices/{id}/release` | 放行；按策略簿决定推不推水位 |
| `POST /api/releases/{id}/ack` | 登记签收回执（签收成功/拒签），争用显式失败 |
| `POST /api/rollback-orders/{id}/resolve` | 乙方案回拨工单闭环 |
| `GET /api/ack/receipts` | 签收列表（只读回执） |
| `GET /api/rollback-orders` | 回拨工单列表 |
| `GET /api/watermarks` | 水位页，含暂停再推消费方 |
| `GET /api/releases` | 放行详情（签收态、回执、工单同行） |
| `GET /api/reconciliation` | 三处读数对读结论 |
| `GET /api/ack/deviations` | 口径偏离留痕 |
